# Wi-Fi Analysis Phase 1 Plan

## 현재 상태

- 130번은 유선과 USB 무선을 동시에 사용하며 NTP가 동기화되어 있다.
- `iw link`에서 BSSID, 채널, RSSI, TX/RX 링크 속도를 읽을 수 있다.
- 현재 드라이버의 `iw station dump`는 비어 있어 Retry 수집은 추가 검증이 필요하다.
- tinySA Ultra+ ZS407은 USB 직렬 장치 `/dev/tinysa4`로 고정 연결되며 2.4GHz 스윕이 동작한다.
- tinySA4는 30초마다 2.400~2.500GHz를 290개 지점으로 측정해 33번에 전송한다.
- 130 장비는 ZS407 기본 안테나와 사용자 확인 레벨 교정 상태를
  `antenna_profile=zs407_stock_antenna`, `calibration_state=level_calibrated`로 저장한다.
- 900MHz 초과 스윕은 측정 직전에 `ultra on`을 실행해 Ultra 입력 경로를 보장한다.
  교정 여부와 안테나 프로필은 장비에서 자동 추정하지 않고 사용자가 명시적으로 관리한다.
- Wi-Fi AP 대역은 8회 연속 스윕의 주파수별 최대값을 Max Hold 원본으로 저장한다.
  `source`, `aggregation`, `sweep_repetitions`로 단일 스윕과 구분한다.
- 기존 무선 스캔은 주변 AP 검색용이며 연결 품질 시계열은 아니다.
- 33번 `collector_rf_sweeps`에는 원본 주파수/전력 배열과 요약값을 함께 저장한다.

## 1차 구현

1. 유선·무선 인터페이스를 명시한 1초 Ping을 동시에 수집한다.
2. 5초마다 RSSI, BSSID, 채널과 링크 속도를 수집한다.
3. 15분 로컬 순환 버퍼와 장애 전후 5분 보존을 구현한다.
4. tinySA USB 연결과 단일 대역 스윕을 구현한다. 완료
5. 정상 구간은 축약하고 장애 창은 1초 원본으로 중앙 전송한다.
6. 규칙 기반 이벤트를 생성하고 누락 원천은 `unknown`으로 유지한다.
7. Omada 컨트롤러 종류, 버전, API와 제공 지표를 조사한다.
8. 33번의 같은 시간축 Grafana 패널은 `network-server`에서 구현한다. 완료

## 현장 및 판단 원칙

- 119번의 활성 현장은 130번에서 모두 조회할 수 있게 연동한다.
- 사용자가 측정 전에 고객사와 현장을 선택하고 측정 세션을 시작한다.
- 33번은 원천 데이터를 보존하고, 119번 보고서는 선택한 측정 세션의 참조만 첨부한다.
- 시스템은 데이터를 자동으로 제외하거나 정상으로 확정하지 않는다.
- 규칙 기반 신호는 `관찰`, `가능성`, `미수집`으로 표시하고 최종 판단은 사용자가 기록한다.
- 현장을 선택하지 않은 원천 데이터는 공용 원천 보관소에 남기되 고객 보고서에 자동 편입하지 않는다.

## 다음 구현

1. GUI에 ZS407 연결 상태, 2.4/5/6GHz 프리셋, 사용자 지정 범위,
   1회 측정 그래프와 자동수집 주기 설정을 제공한다. 완료
2. 현장 선택 후 `measurement_session_id`를 발급하고 RF/Wi-Fi/Ping/LLDP/SNMP 배치에 함께 저장한다.
3. 119번에서 세션의 원본값, 단위, 측정시각, 신선도, 보정상태를 검토한 뒤 보고서에 선택 첨부한다.
4. 안테나 모델과 보정일을 등록한 뒤에만 보정된 절대 전력값으로 표시한다.
5. 5GHz/6GHz 측정은 안테나와 장비 지원범위를 확인한 별도 프로필로 추가한다.

## 중앙 계약

예정 ingress:

```text
POST /api/collectors/:id/wifi-analysis/batches
```

배치는 `batch_id`로 멱등 처리하고 connectivity, Wi-Fi, RF 스윕,
이벤트를 함께 전송한다. 실제 DB migration과 API 구현은
`network-server` 저장소가 소유한다.

## 위험 관리

- 인터페이스 바인딩 후 실제 egress route를 검증한다.
- monitor mode가 필요한 기능은 기본 무선 연결을 끊을 수 있어 1차에서 제외한다.
- tinySA 실제 스윕 시간과 지원 대역은 실장비로 확인한다.
- 정상 1초 데이터를 무제한 중앙 저장하지 않는다.
- 신규 분석기는 기존 heartbeat와 분리된 systemd 서비스로 배포한다.
